# Visualization methodology

Begin with the decision the user wants to make, then select evidence and presentation. Keep this method independent of a particular sensor, algorithm, file name or framework.

1. Identify the question, compared conditions and relevant graph blocks. Inspect existing outputs and generators before deciding to run anything. Discover required execution procedures from graph entry points, relevant project skills and [execution recipes](execution-recipes.md); do not assume the demo executes the user's graph.
2. Establish comparable inputs and measurement domains. Control versions, parameters, ROI, alignment, units and scales. Separate sensor-domain quantities from display-transformed previews. If only one condition was executed, say so; never fabricate a baseline.
3. Choose the smallest useful view. Use aligned images/differences for spatial effects, profiles for local transitions, distributions for population behavior, tables for a few exact numbers, curves for trends and flow diagrams for composition. [report-build](report-building.md) can render supplied images, lines, histogram bins and tables. Interactive controls are useful only when they answer a real question. No universal dashboard or mandatory figure count.
4. Explain how to read the result. Lead with a supported finding and its limitation; label axes, units, legends, ROI and rendering transforms. Use consistent comparison scales or clearly disclose their differences. Keep exact numerical evidence distinct from thumbnails and illustrative diagrams. Include reproduction conditions and source/run identity without overwhelming the main view.
5. Render and inspect when a suitable tool exists. Check contrast, clipping, image alignment, labels, interactions and whether the apparent conclusion agrees with measured values. If rendering cannot be inspected, report that limit separately from numerical checks.
6. Register the durable artifact and present its returned ID through the Visualizations workflow. Follow [change-impact.md](change-impact.md) for historical evidence and any in-scope claims invalidated by findings; a report alone does not authorize changing algorithms.

Use [validation-method.md](validation-method.md) when selecting measurements for an ISP guarantee. Apply project-skill judgment from common.md when a verified reusable procedure emerges.
