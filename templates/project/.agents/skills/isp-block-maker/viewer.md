# Image Viewer and user-selected crops

Read [common.md](common.md) once for local CLI/context/revision rules, including when this guide is linked directly by the app. Read only the sections needed for opening, display control, or crops. For WB, bounded pixel inspection, or reusable input data, read [viewer-analysis.md](viewer-analysis.md). A report request belongs in [Visualizations](../isp-visualizations/SKILL.md); a display request does not itself require cropping.

## Open an image first

For “show this RAW in Image Viewer”, use `node "<workspace>/.isp/tools/isp.mjs" viewer-open "<absolute-input-path>" --spec "<tmpDir>/viewer/input-spec.json"` (or `"<workspace>/.isp/tools/isp.cmd" viewer-open ...` on Windows without Node on PATH). This imports/reuses the exact content+spec, opens Viewer, fits the image, and waits up to 15 seconds for UI acknowledgement. It creates no crop request. Inspect `displayed` and `command.status`; never claim success on import alone. With no connected screen it returns immediately with instructions; pending can mean unsaved UI edits or timeout. Re-present with `viewer-command-show COMMAND_ID` after resolving that condition. `--wait 0` skips acknowledgement waiting. BMP needs no spec. RAW requires known width/height, bitDepth, pattern/group and storage layout; use metadata from the generating code or ask for missing facts. Do not guess from file size alone. RAW spec example: `{"format":"raw","width":4000,"height":3000,"bitDepth":12,"pattern":"GRBG","group":1,"alignment":"lsb"}`. The supported RAW container is 16bit little-endian, not packed RAW10/12.

`viewer-import` only registers; `viewer-show` takes a crop request ID, not an image ID. Prefer `viewer-open` for opening files and reserve `viewer-control` for explicit display adjustments.

## Bidirectional display control and shared views

Read `viewer-view` for the current `live` display metadata. While Image Viewer is visible, the browser refreshes its displayed PNG and metadata about every 1.5 seconds. Check `active`, `updatedAt`, and `sessionId`: only the last reporting screen is represented. There is no manual send button or new saved-view list. One `current-view.png` is replaced, not accumulated as items. Crops still require explicit user addition and remain separate.

Use `viewer-control command.json` to show an image and optionally set zoom, center, render settings, or named highlights. Coordinates are source pixels, top-left origin, exclusive right/bottom. Example (replace IMAGE_ID):

```json
{"imageId":"IMAGE_ID","zoom":2,"center":{"x":1000,"y":700},"render":{"mode":"simple","gamma":2.2,"black":0,"white":4095},"highlights":[{"x":900,"y":600,"width":200,"height":200,"label":"Inspect this edge"}],"message":"Compare the edge texture here"}
```

Zoom is a CSS scale of the generated preview (0.1–512), not a source pixel magnification; previews can be downsampled. `fit:true` overrides zoom. Center is clamped by the viewport edges; in CFA mode it also moves the 1200×1200 source window. Omit render to retain current settings for the same image. On a new RAW image, the default is Simple ISP. Render modes: `simple` (group binning, bilinear demosaic, gamma), `cfa` (individual CFA channels), `gray`, `color` (cell average). RAW bytes are never changed. Simple ISP has no white balance or color matrix. Select levels for the actual source bit depth.

Highlights are visual annotations, separate from selection and saved crops. Send `highlights:[]` to clear them. The user can also clear highlights, change zoom/settings, or right/middle-drag to pan. Do not repeatedly override the user's adjustments. `delivered` counts connected screens, not successful application: check `viewer-command COMMAND_ID` for `applied`/`failed` and acknowledgement time. A closed Viewer or unsaved inspector may delay display. `viewer-command-show COMMAND_ID` presents it again; `show:false` only stores the command. Use a new command for a changed request.

When the user says “look at what I am viewing”, call `viewer-image` (or `viewer-image current`). It returns live coordinates, source image ID, render settings, zoom, highlights and `live.paths.image`. If an image-reading tool is available, read that PNG directly. CLI `viewer-image --vision` returns `nativeImage.path` for an available image-reading tool and never emits image bytes. Integrations supporting native image blocks can request the authenticated attachment API with `vision=true`; forward its image block as native input, never text. Oversized inline images return paths instead. If no image input exists, use metadata and say you cannot inspect the pixels. No external model is invoked automatically.

The current image includes the visible canvas and annotations, not app chrome. It is an 8-bit preview, not numerical RAW data. The PNG is replaced as the user pans or zooms; fetch again for an updated view. After 10 seconds without a report, image access returns an unavailable/stale error. Ask the user to open Image Viewer and display an image; never treat an old image as current. The right crop panel can be resized horizontally. Historic explicitly saved views remain accessible by ID through the legacy API, but new views are not saved as items.

## Source crops and delivery

The user draws a region, then Shift+drags more regions, and clicks **크롭 추가** once to create one saved multi-region item (up to 32 regions). Saving clears the drawing and selects the new item for delivery. **에이전트에게 전달** sends only the selected items with a purpose and shared note, then clears the current delivery choices. Older saved items stay in **이전 크롭** history; showing an old item is inspection, not a new crop. Drawing, saving, sending and agent completion are separate states.

For “the crops I sent”, use `viewer-crops` (GET `/api/viewer/crop-selection`). Read the delivery `id`, `status` (`pending`/`consumed`), `purpose` (`analysis`/`white_balance`/`input`), `description`, `sentAt`, `crops[]` and `missing`. The latest explicit send replaces the previous selection. Process only that delivery, not the whole saved history. The shared description applies to the batch; saved per-item descriptions stay associated with their IDs. A read does not consume the delivery. No sent selection returns null. Deleted/cancelled items must not be recreated or silently substituted. See [viewer-analysis.md](viewer-analysis.md) for compact statistics, WB, input manifests and acknowledgement after processing.

To ask the user for a region:

1. Inspect `viewer-list` and reuse the relevant imported image. Imports may read user-requested image files outside the workspace by absolute path; they copy the source without modifying/deleting it. Relative paths resolve from the active workspace. The size limit is 256MB. Discover `<workspace>` and `<tmpDir>` with `workspace-info`; do not assume the current shell directory is the workspace.
2. Use `viewer-open FILE --spec SPEC_JSON` for an image that should be displayed. `viewer-import` registers without opening. BMP needs `{"format":"bmp"}`; RAW needs actual metadata, for example `{"format":"raw","width":4000,"height":3000,"bitDepth":12,"alignment":"lsb","pattern":"GRBG","group":2,"offset":0,"stride":8000}`. Do not guess width/order from file size alone.
3. Request a region with `viewer-request IMAGE_ID --block BLOCK_ID --purpose white_balance --message "Select neutral, unclipped patches"`, or purpose `input`/`analysis`. The request persists, opens Image Viewer and waits until the user sends crops. Its ID is printed to stderr immediately. For intentional registration-only work use `--no-wait` and check `delivered`; 0 means no screen received it. Unsaved inspector edits defer display. Re-present with `viewer-show REQUEST_ID` instead of creating duplicates.
4. Await the explicit user delivery using the same running CLI process; read [request and wait](viewer-crop-wait.md). `viewer-request` waits continuously by default; if registered with `--no-wait`, run `viewer-wait REQUEST_ID`. Do not finish your turn while the tool process is still waiting. Retain its running handle and poll it. `viewer-result REQUEST_ID` only reads saved items; `submitted` does not mean the user has sent them. Process `delivery.inputs[]` from the fulfilled reply, preserving all grouped regions. Stop on cancellation or a changed task.
5. Re-read before processing. In `crops[]` preserve stable IDs, ROI, description, source/output specs and paths. Single items use `paths.crop`; grouped items use **each `regions[].paths.crop`**. The grouped top-level crop is a ZIP and its ROI/preview is only the first region, not the whole group. Legacy `result` is a first-crop compatibility alias. Descriptions reach the agent only after explicit save; unsaved drafts are not included. Crops may be removed or edited later, so retain the delivery and crop IDs in results.

## RAW geometry and fidelity

RAW is two bytes per pixel, little-endian. `bitDepth` specifies valid bits (8–16); `alignment` is `lsb` or `msb`. `offset` is header bytes; `stride` is row bytes (0 = width × 2). Packed RAW10/12 needs explicit conversion first. Named row-major arrangements are RGGB, GRBG, GBRG and BGGR; do not infer vendor numeric order codes. `group=1/2/4` means Bayer/Tetra/TetraSquare with same-color groups 1×1/2×2/4×4. The full CFA period is 2/4/8 source pixels; originX/originY record phase and default to 0.

Coordinates use original pixels, top-left (0,0), exclusive right/bottom: `[x,x+width) × [y,y+height)`. RAW crops must preserve complete CFA cells and the named pattern at both boundaries, accounting for source origin. The UI aligns each selection and the server rejects unaligned ROIs. Use confirmed coordinates rather than the original drag rectangle. Incomplete cells at frame edges are excluded. RAW crop output preserves pixel bytes exactly with tightly packed rows, removes header/row padding and has zero CFA phase. Historical crops can predate alignment checks; verify their output spec before use.

BMP import supports uncompressed 8-bit palette and 24/32-bit RGB; PNG/JPEG/WebP uploads are browser-decoded 8-bit RGBA. Raster crops are lossless PNG pixels, not the original compressed bytes. A crop preview is an 8-bit image for inspection. Color preview averages same-color groups; Simple ISP bins groups, bilinear-demosaics and applies gamma without WB/color matrix. Neither preview is suitable for numerical RAW measurement.

Each region in a grouped item has its own `roi`, `output`, `sha256` and crop/preview/metadata paths. Do not replace the group with its bounding rectangle. Live display metadata uses `selections[]` for current unsaved rectangles (legacy `selection` is the latest); these are not delivered inputs. Right/middle drag pans; plain drag starts a new selection. Group deletion removes its generated region files, leaving imported originals unchanged.
