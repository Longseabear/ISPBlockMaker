# v0.1.39 · MCP 작업 경로 확장과 Terminal Hub 개선

외부 Claude Code/Codex가 MCP 초기화만으로 독립된 Terminal Hub 소유권을 받습니다. 반복 CLI 실행 없이 화면 표시, 작업 요약, 레시피 관리와 작업 관리 기능을 호출할 수 있습니다.

- 작업 시도·체크포인트·버전 미리보기/전환, 요청 소비/분할, JOB 분할/병합, 프로젝트 스킬 CRUD, 그래프 검사, 하네스 가져오기/내보내기와 Run 미리보기 MCP 도구 추가. 기존 충돌 검사, 복원 미리보기, 요청 중복 방지 유지.
- 외부 연결마다 별도 에이전트 ID를 부여하고 터미널 소유권을 검사합니다. 단일 명령 제출 도구와 입력 전 출력 커서로 빠른 출력 누락을 방지합니다. 입력 수락은 명령 완료를 의미하지 않습니다.
- Terminal 모드 하단에서 Agent CLI / Terminal Hub를 전환할 수 있습니다. 메인 뷰를 유지하며 필요할 때 Hub를 표시하고, 뷰를 숨겨도 세션을 유지합니다.
- Alt+1~5 뷰 이동, Alt+좌우 뷰 순환, Alt+PageUp/PageDown 터미널 탭 이동. 채팅 iframe과 로컬 HTML 리포트에서도 전달합니다.
- 서버 관리자·설치 실행파일·바로가기 아이콘 적용.
- MCP 우선 에이전트 지침, 서버/도구 지연 진단, CLI 타이밍 옵션 및 재현 가능한 벤치마크 추가. CLI 레시피 저장과 시작 경로 최적화.

## 검증 및 범위

전체 테스트 301개 통과 후, 복원 응답 처리 변경에 대한 MCP 회귀 테스트를 추가 실행했습니다.

실제 MCP SDK와 PTY로 외부 연결 분리, 명령 실행, 소유권 거부, 요약 중복 방지를 검사했습니다. 관리 기능은 실제 서버에서 스킬 버전 충돌, JOB 계보 보존, 체크포인트 재시도, 복원 미리보기를 검증합니다. Terminal Hub 도킹과 뷰 유지, 모드 전환 후 입력, 단축키 재열기를 브라우저에서 확인했습니다.

로컬 소규모 벤치마크에서 MCP 주요 호출은 수십 ms, CLI는 약 115~156ms였습니다. 보고된 다른 PC의 30~120초 지연은 재현되지 않았으므로 해결됐다고 단정하지 않습니다. 진단 절차는 `docs/agent-bridge-audit.md`를 참고하세요.

MCP는 지속 연결과 내부 루프백 API를 사용합니다. CLI 자체는 제거하지 않았으며, 오프라인 리포트 생성·아카이브 파일 처리·설치/실행 같은 로컬 유틸리티는 유지합니다.

## 업데이트 후

워크스페이스 서버를 재시작하고 외부 MCP 클라이언트를 한 번 재연결하세요. 도구 목록과 연결별 소유권이 갱신됩니다. 이전 CLI 지침을 계속 따르는 기존 대화는 새 대화에서 시작하세요. 사용자 수정 스킬은 자동 덮어쓰기 대신 기존 업데이트 후보 정책을 따릅니다.
