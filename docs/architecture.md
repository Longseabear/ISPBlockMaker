# ISP Block Maker — 설계 초안

상태: 최초 요구사항 논의 기록. 현재 구현은 [README](../README.md)를 기준으로 한다.

2026-09-13 구현 결정: MCP 대신 HTTP CLI bridge + WebSocket을 채택했다. 평면 그래프, JSON 내 설명, 실제 cmd 터미널, 이미지/HTML 결과물 및 실행 가능한 합성 영상 예제를 구현했다. 아래의 MCP 도구, 정의/인스턴스 분리, 하위 그래프 및 별도 Markdown 설명은 초기 제안으로 남아 있으며 현재 구현 기능이 아니다.

## 목적

웹에서 ISP IP 블록을 구성하고, 로컬 Claude Code / Codex와 함께 구현·검증하며 결과를 확인한다. 초기 실행 환경은 Windows 로컬 PC의 브라우저와 로컬 서버를 가정한다.

## 화면

- 중앙: 블록 그래프. 노드 추가·연결·선택 및 하위 블록 탐색.
- 오른쪽: 선택 블록의 설명, 동작 원리, 입출력, 파라미터, 구현 파일, 검증 상태.
- 하단: 실제 셸 세션을 제공하는 터미널. Claude Code와 Codex는 세션별로 실행.
- 별도 탭 또는 분할 패널: 이미지·HTML·차트 등 시각화 결과. 블록/실행별로 필터링.

## 구성

브라우저 → 로컬 서비스 → 프로젝트 파일이라는 구조를 사용한다.

브라우저와 로컬 서비스는 HTTP로 상태를 읽고 변경하며 WebSocket으로 터미널 입출력 및 상태 변경을 전달한다. 로컬 서비스가 PTY 프로세스, 프로젝트 상태, 결과물 등록을 관리한다. 별도 MCP 어댑터는 같은 서비스를 호출하여 에이전트에 블록 정보를 제공한다.

제안 기술: React + TypeScript, React Flow, xterm.js, Node.js + node-pty. Windows PTY 동작과 설치된 CLI의 대화형 실행 호환성을 구현 초기에 검증한다.

## 그래프 원본과 문서

Mermaid를 원본 편집 형식으로 사용하지 않는다. 구조화된 JSON을 원본으로 저장하고 Mermaid는 문서 내보내기로 생성한다. 설명과 알고리즘은 블록별 Markdown으로 분리한다. 소스코드와 대용량 입력·결과 데이터는 경로로 참조한다.

블록 정의와 블록 인스턴스를 분리하여 같은 알고리즘을 다른 파라미터로 재사용한다. 각 인스턴스는 고유 ID, 정의 ID, 파라미터, 화면 위치, 상위 블록 ID를 갖는다. 간선은 노드 ID뿐 아니라 출력/입력 포트 ID를 연결한다. 화면 배치 변경은 알고리즘 변경과 구분한다.

블록 정의에 포함할 정보:

- 이름, 목적, 동작 원리, 수식 및 구현상의 가정
- 입력/출력 포트: 데이터 유형, shape, bit depth, 수치 표현, Bayer 패턴 등
- 파라미터: 타입, 기본값, 허용 범위, 단위
- 구현 언어와 파일, 진입점, 테스트 및 참조 결과
- 상태: 초안, 구현됨, 검증됨. 검증됨은 구체적인 테스트 실행에 연결
- 하위 그래프 참조 및 외부 포트와 내부 포트의 매핑

예를 들어 flat-detection은 flat mask를 출력하고 denoise는 image와 flat mask를 별도 입력으로 받는다. 단순한 노드 순서보다 실제 데이터 흐름을 표현해야 한다. 초기 실행 그래프는 DAG로 제한하며 반복 처리는 블록 내부 구현으로 둔다.

## 에이전트에 제공하는 정보

제안 MCP 도구:

- get_project: 프로젝트 개요, 그래프 및 현재 revision
- get_selection: 해당 UI/터미널 세션에서 선택한 블록
- get_block: 설명, 포트, 파라미터, 구현 파일 및 연결된 블록
- get_block_context: 작업에 필요한 상하류 정보와 관련 결과물
- update_block: 예상 revision을 지정한 블록 수정
- register_artifact: 블록 및 실행과 연결된 결과물 등록

도구 이름은 애플리케이션 자체 계약이다. 현재 CLI에 내장된 도구가 아니다. Codex와 Claude Code에 ISP Block Maker의 MCP 서버를 각각 연결한다. UI 선택이 에이전트 대화에 자동 주입되는 것은 아니므로 작업 시작 시 도구를 호출하도록 프로젝트 지침을 제공한다. 실행 중 작업의 대상 블록은 고정하고 사용자가 다른 노드를 클릭해도 바뀌지 않게 한다.

프로젝트 상태는 로컬 서비스가 단일 쓰기 경로를 맡는다. revision 충돌 시 덮어쓰지 않고 다시 읽도록 응답한다. 에이전트의 소스 파일 수정은 허용하되 구조화된 상태 변경은 API로 처리한다. 파일 변경 감지는 UI 갱신에 활용한다.

## 시각화

이미지와 HTML을 모두 지원하는 artifact 모델을 사용한다. 정적 비교는 PNG/JPEG, 파라미터 슬라이더·곡선·확대 비교는 HTML이 적합하다. RAW 파일은 브라우저에서 바로 이미지로 표시하지 않고 원본과 표시용 변환 결과를 함께 연결한다.

artifact는 ID, 종류, 제목, 블록 ID, 실행 ID, 생성 시간, 프로젝트 내 상대경로를 기록한다. 실행 기록에는 사용한 블록 revision, 코드 버전 또는 해시, 입력, 파라미터, 상태를 보관하여 예전 결과와 현재 결과를 구별한다.

생성 HTML은 격리된 iframe에서 렌더링한다. 스크립트가 필요해도 앱과 동일 출처 권한이나 로컬 제어 API 접근은 주지 않는다. 로컬 서비스는 loopback 바인딩, Origin/Host 검사 및 세션 인증을 적용한다. 결과물 경로는 허용된 프로젝트 영역 안에서만 해석한다.

## 초기 MVP 제안

1. 프로젝트 저장/불러오기, 노드 추가/연결/선택, 블록 설명 편집.
2. 실제 로컬 터미널과 CLI 수동 실행, 중단 및 크기 변경.
3. MCP를 통한 선택 블록과 관련 구현 정보 조회.
4. 에이전트 생성 이미지/HTML 등록과 표시.
5. flat-detection → denoise 예제로 위 흐름 검증.

하위 그래프 편집, RTL 생성, 자동 파이프라인 실행, 정교한 영상 비교는 후속 단계 후보이다. 최초 IP 구현 언어와 검증 데이터 형식은 아직 확정하지 않았다.
