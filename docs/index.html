01 — GET STARTED

설치는 짧게.
작업은 내 폴더에서.

Windows x64 설치파일에는 Node와 서버 실행 의존성이 들어 있습니다. 사용 PC에서 별도로 npm install을 할 필요가 없습니다.

01

설치파일 실행

최신 릴리즈에서 ISPBlockMaker-Setup.exe를 받아 실행하세요. 설치 후에는 새 터미널을 여세요.

서명되지 않은 초기 버전입니다. 릴리즈에 SHA-256 파일을 함께 제공합니다.
02

작업 폴더에서 시작

프로젝트 폴더로 이동한 뒤 실행합니다. 새 폴더면 그래프와 로컬 에이전트 지침을 준비합니다.

cd C:\Work\MyISP
isp-block-maker .
03

브라우저에서 작업

로컬 서버와 브라우저가 열립니다. 상단 프로젝트 이름에서 기존 작업 폴더를 선택하세요. 해당 폴더의 서버에 연결하며, 서버가 없으면 자동으로 시작합니다. 기존 서버와 터미널은 유지됩니다.

시작 메뉴로 실행하면 폴더를 선택할 수 있습니다. 기본 주소는 http://127.0.0.1:4310입니다.
별도로 준비할 환경

버전 관리는 Git, Python 알고리즘 실행은 Python과 프로젝트 패키지가 필요합니다. Claude Code / Codex와 모델 접속 환경은 별도로 준비하세요. 폐쇄망에서도 앱 자체는 로컬로 실행되지만, 에이전트가 사용할 모델 연결은 조직의 환경에 따라 달라집니다.

이 사이트는 설치·사용 안내입니다. GitHub Pages에서 터미널이나 ISP 서버를 실행하지는 않습니다.

의도를 남기고,

사용자는 평문으로 요청합니다. 에이전트는 블록의 입출력과 구현을 읽고, 요청을 JOB으로 나누어 처리할 수 있습니다.

03 — INSPECT THE IMAGE

같은 픽셀을 보며
이야기하세요.

이미지와 좌표, 렌더링 조건을 에이전트와 공유합니다. 현재 View는 실시간으로, 크롭은 여러 영역을 한 항목으로 묶어 다룹니다.

올바른 조건으로 열기

BMP / PNG / JPEG 또는 RAW를 열 수 있습니다. RAW는 너비·높이, 유효 비트, 정렬, CFA 배열, 그룹을 지정하세요. 현재 10/12bit RAW는 픽셀당 2바이트, little-endian 컨테이너를 사용합니다.

CFA colors는 배열 그대로, Simple ISP는 같은 색 그룹 평균 → bilinear 보간 → 감마를 적용합니다. WB·CCM이나 고급 remosaic은 포함하지 않습니다.

이동하고, 선택하고, 공유하기

  • 휠 — 마우스 위치 중심 확대·축소
  • 오른쪽 / 가운데 버튼 드래그 — 이미지 이동
  • 왼쪽 드래그 — 첫 영역 선택
  • Shift+드래그 반복 → 추가 — 여러 영역을 한 크롭 항목으로 저장
  • Shift+크롭 항목 클릭 — 범위 선택 후 한 번에 전달
  • 오른쪽 아래 정보 — 해석 조건·에이전트 안내 열기

각 RAW 영역은 CFA 주기를 유지하도록 정렬됩니다. 일반 드래그는 새 선택을 시작하고, Esc로 선택을 취소합니다. 그리기만으로는 저장되지 않습니다.

ONE ITEM, MULTIPLE REGIONS

여러 영역, 하나의 설명.

  1. 첫 영역을 드래그하고, Shift를 누른 채 추가 영역을 드래그합니다.
  2. 추가 (N)를 누르면 오른쪽 목록에 영역 N개를 가진 항목 하나가 생깁니다.
  3. 그 항목에 설명을 쓰고 저장 아이콘을 누릅니다.
  4. 항목을 선택한 뒤 크롭 묶음 전달을 누르고 에이전트에게 검토를 요청하세요.

좌표와 파일은 영역별로 유지됩니다. 묶음은 ZIP으로 다운로드하거나 한 번에 삭제할 수 있습니다. 아래는 크롭 패널을 연 화면입니다.

YOU → AGENT
지금 보고 있는 부분을 봐줘. 경계가 깨지는 원인을 설명해줘.

Viewer가 열려 있으면 현재 보이는 영역과 렌더링 정보를 공유합니다. 이미지 직접 전달은 에이전트의 이미지 입력 도구가 지원할 때 가능합니다.

AGENT → YOU
이 RAW를 GRBG / Tetra 2×2 / 10bit로 열고, 관심 영역을 확대해서 강조해줘.

에이전트는 이미지를 등록하고 확대·이동·강조를 요청할 수 있습니다. 크롭 파일과 사용자가 저장한 설명도 읽을 수 있습니다.

JOB PLANNING · v0.1.13

등록하고, 나누고,
합쳐서 진행하세요.

에이전트에게 “이 내용을 JOB으로 등록해. 아직 구현하지 마”라고 요청하세요. 메모 없이 직접 등록할 수 있으며, 생성된 작업은 JOB Queue에 대기 상태로 표시됩니다.

작업을 나누거나 합치기

“이 JOB을 구현과 검증으로 나눠줘”, “이 두 JOB을 하나로 합쳐줘”처럼 요청할 수 있습니다. 같은 블록 또는 같은 전체 그래프의 대기 JOB끼리 지원합니다. 원본은 새 JOB으로 교체되고 내용·요청 연결·분할/병합 이력이 보존됩니다.

등록과 실행은 별도

등록·분할·병합만 요청하면 구현은 시작하지 않습니다. 진행 중이거나 완료된 JOB은 자동으로 재편하지 않으며, 먼저 작업 상태를 확인하고 명시적으로 대기로 되돌려야 합니다. 기존 에이전트에는 프로젝트 스킬을 다시 읽도록 요청하세요.

중간 결과물

최근 50개 커밋 또는 직접 입력한 커밋 해시로 특정 시점을 확인합니다. 태그를 붙이지 않은 실험도 찾아볼 수 있습니다.

선택 → 변경 확인 → 적용

  1. 태그·브랜치·커밋 중 원하는 버전을 선택합니다.
  2. 변경된 블록·간선·파일을 미리 확인합니다.
  3. 선택한 버전 적용을 누르면 그래프와 구현 코드가 함께 전환됩니다.

선택만으로는 코드가 바뀌지 않습니다. 적용하면 해당 서버의 연결된 터미널은 종료되고, 로컬 요청·JOB·시각화 기록은 유지됩니다. 미커밋 변경이 있으면 먼저 커밋하거나 정리해야 합니다.

태그가 아직 없다면

태그는 자동 생성하지 않습니다. 프로젝트 폴더에서 완성된 작업을 커밋한 뒤 태그를 만들고, UI의 목록 새로고침을 누르세요. 일반 태그와 주석 태그를 모두 지원합니다.

git tag -a denoise-v1 -m "Validated denoise baseline"

위 명령은 현재 커밋에 새 이름을 붙입니다. 태그·커밋 적용은 Detached HEAD로 열리며, 이어서 개발할 브랜치는 git switch -c denoise-next처럼 만듭니다. 예시 이름이 이미 있으면 다른 이름을 사용하세요.

상단 태그명은 현재 커밋에 붙은 태그를 뜻합니다. 별표(*)는 미커밋 변경 표시입니다. 태그 이력도 번들로 공유하려면 Git 이력 포함을 선택하세요.

04 — HAND OFF YOUR WORK · NEW IN v0.1.9

작업의 맥락까지,
.bundle 하나로.

그래프와 코드뿐 아니라 요청/JOB, 시각화, 이미지와 크롭을 한 파일에 담습니다. 상대방은 새 폴더에 복원하고 바로 이어서 작업합니다.

보내는 사람

저장하고, 한 파일로 보내세요.

먼저 편집한 설명·요청을 저장하고 에이전트의 파일 수정을 잠시 멈추세요. 상단 공유에서 프로젝트 이름으로 지정된 저장 파일명, 포함/제외 파일과 용량을 확인한 뒤 .bundle 저장을 누릅니다. UI에서는 Adaptive denoise.bundle처럼 프로젝트 이름이 기본 파일명이 됩니다. 한글과 공백은 유지하고 파일명에 쓸 수 없는 문자는 정리합니다. CLI에서는 -o로 이름을 직접 지정합니다.

isp-block-maker pack . -o denoise.bundle

UI에서 받은 프로젝트이름.bundle 또는 위 명령으로 만든 denoise.bundle 파일과 설치 링크를 상대방에게 보내면 됩니다. CLI는 기존 번들 파일을 덮어쓰지 않으므로 새 이름을 사용하세요.

받는 사람

새 폴더에서 이어서 시작.

UI로 열려면 v0.1.10 이상에서 상단 번들 열기를 누르고 파일과 새 복원 폴더를 선택하세요. 명령어로 열기도 가능합니다. 부모 폴더 C:\Work를 준비하고, 번들을 받은 폴더에서 아래 명령을 실행합니다. denoise는 아직 존재하지 않는 새 폴더여야 합니다.

isp-block-maker open denoise.bundle
  --into C:\Work\denoise

위 명령은 한 줄로 실행하세요. 받은 파일명에 공백이 있으면 isp-block-maker open "Adaptive denoise.bundle" --into C:\Work\denoise처럼 따옴표로 감쌉니다. 파일 검증과 복원, 프로젝트 로컬 도구 초기화 후 서버와 브라우저를 엽니다. 기존 폴더는 덮어쓰지 않습니다.

함께 전달되는 내용
항목기본 동작알아둘 점
그래프 · 구현 · 지침포함graph.json, 소스, 테스트, 프로젝트 스킬 및 의존성 명세
요청/JOB · 활동포함로컬 프로젝트 기록과 저장된 요청을 유지합니다.
시각화 · SDD · 크롭포함파일, 좌표와 저장된 설명을 함께 보존합니다.
Viewer 원본 이미지기본 포함 / 선택 해제 가능제외하면 기존 크롭은 다운로드할 수 있지만 원본 미리보기·새 크롭은 제한됩니다.
Git 이력기본 제외 / 선택 포함독립 프로젝트의 브랜치·태그·HEAD를 복원하고 미커밋 코드를 보존합니다. Git 설치가 필요합니다.
접속 토큰 · 실행 환경제외로컬 연결정보와 도구는 재생성합니다. Python 패키지·모델 연결은 별도로 준비하세요.

필요에 맞게 조절하기

# Viewer 원본 제외
isp-block-maker pack . -o small.bundle --without-images
# Git 이력 포함
isp-block-maker pack . -o history.bundle --with-git
# 포함 목록과 용량만 확인
isp-block-maker pack . --dry-run

복원만 하려면

open 명령 끝에 --no-open을 붙이면 복원과 초기화만 하고 서버는 열지 않습니다. 이후 해당 폴더에서 isp-block-maker .로 시작하세요.

원본 없이 받은 경우, 동일 이미지와 설정을 에이전트가 viewer-open으로 다시 등록하면 누락된 원본을 복구할 수 있습니다. 외부 절대경로로 참조한 입력 데이터는 별도로 맞춰주세요.

포함 목록을 확인하세요.

접속정보, 알려진 비밀 파일명, 개인 에이전트 설정, 가상환경, node_modules, 링크는 자동 제외합니다. 다만 소스 안에 직접 적은 API 키는 검사하지 않습니다. Git 이력을 선택하면 과거 커밋 내용도 함께 전달됩니다.

검증 후 새 폴더에 복원합니다.

파일 경로와 SHA-256/CRC를 검사합니다. 형식 버전 1의 ZIP 저장 방식이며, 최대 2 GiB / 10,000개 파일 / 파일당 256 MiB를 지원합니다. 일반 ZIP이나 Git의 git bundle과는 다릅니다. 보내는 중 파일 변경이 감지되면 다시 저장하세요.

번들은 한 시점의 작업 사본입니다. 지속적인 공동 개발에는 프로젝트의 독립 Git 원격 저장소를 함께 사용하세요. Git 원격 설정과 훅, 실행 중인 터미널·실시간 View는 전달하지 않습니다.

폐쇄망에서도 사용할 수 있나요?

설치파일에 Node와 서버 의존성이 포함되어 있어 앱 자체는 인터넷 없이 실행할 수 있습니다. Git·Python 패키지와 에이전트 모델 접속은 별도이며, 조직에서 허용하는 방법으로 준비해야 합니다.

기존 폴더를 열면 “폴더별 서버입니다”라고 나와요.

v0.1.12에서 수정했습니다. 실행 중인 이전 앱 서버를 종료하고 최신 설치파일로 업데이트한 뒤 다시 실행하세요. 상단 프로젝트 이름 → 폴더 경로 → 찾아보기 → 이 폴더에서 작업으로 엽니다. 해당 폴더의 서버가 없으면 자동 시작하고, 이미 실행 중이면 연결합니다. 폴더별로 주소의 포트가 달라질 수 있습니다.

이미 복원한 프로젝트는 폴더 선택으로 여세요. 번들 열기는 .bundle 파일을 새로운 폴더에 복원할 때 사용합니다. 폴더를 바꿔도 이전 서버와 터미널은 유지됩니다.

설치 후 명령어가 인식되지 않아요.

설치 이전에 열려 있던 터미널을 닫고 새 터미널에서 실행하세요. 시작 메뉴의 ISP Block Maker로도 실행할 수 있습니다.

에이전트가 프로젝트 도구를 못 찾으면요?

프로젝트 루트의 AGENTS.md 또는 CLAUDE.md와 .agents/skills/isp-block-maker/SKILL.md를 읽도록 요청하세요. 서버 실행 후 프로젝트 폴더에서 node .isp/tools/isp.mjs context로 연결을 확인할 수 있습니다.

GitHub Pages 주소를 보내면 같이 작업할 수 있나요?

이 페이지는 공개 안내 사이트입니다. 실제 앱은 각자의 PC에서 실행합니다. 현재 동시 편집용 원격 협업 서비스는 아니므로 Git이나 .bundle 파일로 작업을 공유하세요.

가이드에 보이는 예제가 설치파일에도 있나요?

아니요. 스크린샷은 안내용 샘플 그래프와 합성 이미지로 촬영했습니다. 사용자 프로젝트와 예제 알고리즘은 프레임워크 릴리즈에 포함하지 않습니다.
