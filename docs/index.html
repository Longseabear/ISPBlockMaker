01 — GET STARTED

설치는 짧게.
작업은 내 폴더에서.

Windows x64 설치파일에는 Node와 서버 실행 의존성이 들어 있습니다. 사용 PC에서 별도로 npm install을 할 필요가 없습니다.

01

설치파일 실행

최신 릴리즈에서 ISPBlockMaker-Setup.exe를 받아 실행하세요. 설치 후에는 새 터미널을 여세요.

서명되지 않은 초기 버전입니다. 릴리즈에 SHA-256 파일을 함께 제공합니다.
02

작업 폴더에서 시작

프로젝트 폴더로 이동한 뒤 실행합니다. 새 폴더면 그래프와 로컬 에이전트 지침을 준비합니다.

cd C:\Work\MyISP
isp-block-maker .
03

브라우저에서 작업

로컬 서버와 브라우저가 열립니다. 상단 프로젝트 이름에서 다른 작업 폴더를 선택할 수도 있습니다.

시작 메뉴로 실행하면 폴더를 선택할 수 있습니다. 기본 주소는 http://127.0.0.1:4310입니다.
별도로 준비할 환경

버전 관리는 Git, Python 알고리즘 실행은 Python과 프로젝트 패키지가 필요합니다. Claude Code / Codex와 모델 접속 환경은 별도로 준비하세요. 폐쇄망에서도 앱 자체는 로컬로 실행되지만, 에이전트가 사용할 모델 연결은 조직의 환경에 따라 달라집니다.

이 사이트는 설치·사용 안내입니다. GitHub Pages에서 터미널이나 ISP 서버를 실행하지는 않습니다.

02 — WORK WITH AN AGENT

의도를 남기고,
결과를 함께 확인하세요.

사용자는 평문으로 요청합니다. 에이전트는 블록의 입출력과 구현을 읽고, 요청을 JOB으로 나누어 처리할 수 있습니다.

1

블록을 선택하고 연결하기

Add block으로 추가하고 포트를 드래그해 연결하세요. 설명 보기에서 사용자 설명, Shared I/O, 에이전트 설명을 확인합니다.

2

원하는 변경을 평문으로 남기기

노드의 말풍선 버튼 → User requests에 입력하고 Save changes로 저장하세요. 전체 그래프 요청은 왼쪽 위 떠 있는 요청 버튼에 남깁니다.

3

터미널에서 에이전트에게 요청하기

기본 셸은 자동 연결됩니다. 에이전트를 바꾸려면 Stop 후 Terminal agent에서 선택하세요.

프로젝트 스킬을 읽고 Block 메모한 거 전부 구현해줘. 입출력 설명을 갱신하고 변경된 블록과 결과를 보여줘.
4

코드 · 시각화 · 문서 검토하기

Node implementations에서 연결된 소스를, Visualizations에서 HTML·이미지 결과를 확인하세요. Documentation에서는 Overview → Flow → 블록 상세 순서의 SDD 작성을 요청할 수 있습니다.

RESULTS, AT A GLANCE

시각화는 넓게,
필요할 때 다시 터미널로.

Visualizations의 확대 아이콘을 누르면 결과 화면에 집중할 수 있습니다. 다시 누르면 이전 배치로 돌아갑니다.

아래 스크린샷의 그래프는 측정 결과가 아닌 안내용 예시입니다.
03 — INSPECT THE IMAGE

같은 픽셀을 보며
이야기하세요.

이미지와 좌표, 렌더링 조건을 에이전트와 공유합니다. 현재 View는 실시간으로, 크롭은 선택한 영역별로 다룹니다.

올바른 조건으로 열기

BMP / PNG / JPEG 또는 RAW를 열 수 있습니다. RAW는 너비·높이, 유효 비트, 정렬, CFA 배열, 그룹을 지정하세요. 현재 10/12bit RAW는 픽셀당 2바이트, little-endian 컨테이너를 사용합니다.

CFA colors는 배열 그대로, Simple ISP는 같은 색 그룹 평균 → bilinear 보간 → 감마를 적용합니다. WB·CCM이나 고급 remosaic은 포함하지 않습니다.

이동하고, 선택하고, 공유하기

  • 휠 — 마우스 위치 중심 확대·축소
  • 오른쪽 / 가운데 버튼 드래그 — 이미지 이동
  • 왼쪽 드래그 → 크롭 추가 — 영역 저장
  • Shift+크롭 항목 클릭 — 범위 선택 후 한 번에 전달
  • 오른쪽 아래 정보 — 해석 조건·에이전트 안내 열기

RAW 크롭은 CFA 주기를 유지하도록 정렬됩니다. Shift+이미지 드래그도 이동에 사용할 수 있습니다.

YOU → AGENT
지금 보고 있는 부분을 봐줘. 경계가 깨지는 원인을 설명해줘.

Viewer가 열려 있으면 현재 보이는 영역과 렌더링 정보를 공유합니다. 이미지 직접 전달은 에이전트의 이미지 입력 도구가 지원할 때 가능합니다.

AGENT → YOU
이 RAW를 GRBG / Tetra 2×2 / 10bit로 열고, 관심 영역을 확대해서 강조해줘.

에이전트는 이미지를 등록하고 확대·이동·강조를 요청할 수 있습니다. 크롭 파일과 사용자가 저장한 설명도 읽을 수 있습니다.

04 — HAND OFF YOUR WORK

공유할 것은,
작업 워크스페이스입니다.

받는 사람은 ISP Block Maker를 설치한 뒤 프로젝트 폴더를 엽니다. 앱 설치폴더와 알고리즘 프로젝트는 따로 관리합니다.

계속 함께 개발할 때

그래프 + 코드는 Git으로

프로젝트의 독립 저장소에 graph.json, 구현 소스, 테스트, 의존성 명세와 프로젝트 지침을 커밋·푸시하세요. 상대방은 clone한 폴더에서 실행합니다.

isp-block-maker .

Git clone만으로 요청/JOB, 시각화, Viewer 이미지·크롭은 따라오지 않습니다. 기본적으로 .isp/는 Git 제외입니다.

결과와 진행 상태까지 넘길 때

프로젝트 사본을 ZIP으로

저장을 마친 뒤 서버와 에이전트의 쓰기 작업을 종료하세요. 별도 공유용 폴더에 아래 파일을 복사하고 ZIP으로 묶습니다. 원본 프로젝트의 파일은 지우지 마세요.

받는 사람은 새 폴더에 풀고 isp-block-maker .로 시작합니다. 코드 실행에 필요한 Python 패키지와 외부 입력 파일도 별도로 준비해야 합니다.

공유용 ZIP에 담을 파일
내용파일 / 폴더언제 필요한가요?
그래프와 구현graph.json, 구현 소스, 테스트, 의존성 명세항상. 구현 경로와 폴더 구조를 유지하세요.
프로젝트 지침AGENTS.md, CLAUDE.md, .agents/skills/, .claude/skills/같은 작업 규칙을 적용할 때
요청 · JOB · 결과 목록.isp/project.json작업 상태를 이어받을 때
시각화 · SDD 실물.isp/artifacts/결과 목록과 함께 포함
Viewer 이미지 · 크롭.isp/viewer/등록된 이미지, 좌표, 설명, 크롭 파일 공유
활동 기록.isp/activity.json작업 요약과 과거 활동을 볼 때
추가 입력 · 생성 파일필요한 데이터, artifacts/generated/ 등구현에서 참조하는 파일을 빠뜨리지 않기

복사하지 않을 것

.isp/connection.json은 현재 PC 서버의 접속 토큰입니다. .isp/tools/와 함께 공유에서 제외하세요. 새 PC에서 실행할 때 다시 생성됩니다. API 키, .env, 에이전트 인증·개인 설정도 제외하세요.

상대 PC에서 확인할 것

처음에는 같은 앱 버전을 사용하세요. 절대경로로 작성한 코드나 과거 View 스냅샷 경로는 조정이 필요할 수 있습니다. 그래프, 구현, 시각화, 크롭 파일을 각각 열어 확인하세요. 터미널 세션과 실시간 View는 새 PC에서 다시 시작합니다.

Git 이력까지 전달하려면 Git 원격 저장소를 함께 공유하세요. HTML SDD만 검토받을 경우, 독립 실행 가능한 HTML 파일 하나로 전달할 수도 있습니다. 현재 앱에는 통합 워크스페이스 내보내기 버튼이 없습니다.

GOOD TO KNOW

시작 전에
궁금한 것들.

폐쇄망에서도 사용할 수 있나요?

설치파일에 Node와 서버 의존성이 포함되어 있어 앱 자체는 인터넷 없이 실행할 수 있습니다. Git·Python 패키지와 에이전트 모델 접속은 별도이며, 조직에서 허용하는 방법으로 준비해야 합니다.

설치 후 명령어가 인식되지 않아요.

설치 이전에 열려 있던 터미널을 닫고 새 터미널에서 실행하세요. 시작 메뉴의 ISP Block Maker로도 실행할 수 있습니다.

에이전트가 프로젝트 도구를 못 찾으면요?

프로젝트 루트의 AGENTS.md 또는 CLAUDE.md와 .agents/skills/isp-block-maker/SKILL.md를 읽도록 요청하세요. 서버 실행 후 프로젝트 폴더에서 node .isp/tools/isp.mjs context로 연결을 확인할 수 있습니다.

GitHub Pages 주소를 보내면 같이 작업할 수 있나요?

이 페이지는 공개 안내 사이트입니다. 실제 앱은 각자의 PC에서 실행합니다. 현재 동시 편집용 원격 협업 서비스는 아니므로 Git이나 프로젝트 사본으로 작업을 공유하세요.

가이드에 보이는 예제가 설치파일에도 있나요?

아니요. 스크린샷은 안내용 샘플 그래프와 합성 이미지로 촬영했습니다. 사용자 프로젝트와 예제 알고리즘은 프레임워크 릴리즈에 포함하지 않습니다.
