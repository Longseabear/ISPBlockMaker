# Terminal Hub

사이드바 **Project Skills 위의 Terminal Hub**에서 세션을 선택하거나 새로 만듭니다. SSH, 개발 서버, 빌드 등 실제 PTY 셸의 출력과 입력을 사용자와 에이전트가 공유합니다. 기존 Interaction/Terminal 모드를 바꾸지 않습니다.

- 에이전트가 세션을 만들거나 명령을 보내도 화면은 자동으로 열리지 않습니다.
- 로그인·사용자 입력, 함께 봐야 할 오류·출력 등 필요한 시점에 에이전트가 표시를 요청합니다. 키보드 포커스는 가져오지 않습니다. 편집 중이면 알림만 표시합니다.
- 사용자는 언제든 아이콘으로 열고 바로 입력할 수 있습니다. 사용자 입력이 우선하며, 제출 후 잠시 입력이 없으면 연결된 에이전트가 최신 상태로 자동 재개할 수 있습니다.
- **Ctrl+C**는 전경 작업을 중단하며 사용자 입력 우선 규칙을 따릅니다. **세션 종료**는 셸과 하위 프로세스를 종료합니다. 종료된 세션의 출력은 **목록에서 삭제**하기 전까지 확인할 수 있습니다.
- 패널 숨김, 다른 화면 선택, 브라우저 연결 해제는 실행을 중단하지 않습니다. 앱 서버 종료·재시작, 구현 버전 전환, 워크스페이스 교체 시에는 세션이 종료됩니다. 세션과 로그는 디스크에 영구 저장하지 않습니다.

SSH는 처음부터 이 셸에서 실행해야 합니다. 다른 도구가 이미 실행한 프로세스를 가져오지는 않습니다. 전경 서버가 실행 중인 셸에 다른 명령을 보내면 서버의 표준 입력으로 전달되므로, 별도 작업에는 새 세션을 사용하세요.

## MCP와 스킬

로컬 `isp-workspace` MCP에 다음 도구가 제공됩니다. 공개 MCP 공유에는 포함되지 않습니다. 새 카탈로그가 보이지 않는 기존 에이전트는 MCP를 다시 연결하거나 새 대화에서 시작하세요.

| 도구 | 동작 |
| --- | --- |
| `list_shared_terminals` | 세션 제목·상태·입력 소유자 조회 |
| `create_shared_terminal` | UUID `session_id`, 제목으로 백그라운드 셸 생성 |
| `write_shared_terminal` | UUID `request_id`와 정확한 입력 전송. 실행하려면 `\r` 포함 |
| `read_shared_terminal` | `cursor` 이후 출력 조회. 반환된 cursor를 다음 조회에 사용 |
| `present_shared_terminal` | `input/error/inspect/user` 사유와 설명으로 화면 표시 요청 |
| `stop_shared_terminal` | 셸과 프로세스 종료 |
| `remove_shared_terminal` | 종료된 세션 제거 |

`isp-shared-terminal` 스킬이 배경 실행, 필요한 때만 표시, 사용자 개입 확인, 세션 정리 기준을 안내합니다. UI 판단은 에이전트가 하며, 문자열 매칭으로 모든 오류를 팝업하지 않습니다.

## 데이터와 부하

화면 출력은 인증된 WebSocket으로 열린 세션에만 전송합니다. 숨긴 화면은 출력 스트림에서 분리되고 세션 메타데이터 변경만 받습니다. 모델에게는 출력이 자동 주입되지 않으며 MCP로 필요한 부분을 조회합니다.

세션은 워크스페이스 최대 16개, 에이전트당 최대 4개(종료 후 보관 중인 세션 포함), 세션별 최근 출력은 200,000 UTF-16 코드 단위, MCP 출력은 호출당 최대 24,000 단위입니다. 오래된 출력 유실은 `truncated`, 남은 출력은 `hasMore`로 알립니다. `userInputSequence`는 사용자 입력 개입 횟수입니다. `running`은 셸이 살아 있다는 뜻이며 개별 명령 완료를 보장하지 않습니다.

입력 재시도에는 동일 `request_id`를 사용합니다. 같은 세션에서 같은 ID의 동일 입력은 다시 실행하지 않으며 다른 입력을 같은 ID로 보내면 거부합니다. 에이전트 입력 ID 기록은 세션당 4,096개로 제한하며 오래된 ID를 지워 재실행 가능하게 만들지 않습니다. 사용자 WebSocket 입력은 자동 재시도하지 않으며 ID 기록에 쌓지 않습니다. 네트워크 연결이 끊긴 사용자 입력은 자동 재전송하지 않습니다.

REST는 `/api/shared-terminals`와 `/:id/output`, `input`, `control`, `present`, `stop`을 사용합니다. 기존 로컬 인증·Origin 검사·버전 전환 보호가 적용됩니다. 입력과 출력 본문은 활동 기록에 저장하지 않습니다. 터미널에는 명령이 출력한 민감정보가 포함될 수 있습니다.

## 여러 에이전트의 식별과 키 연결

외부 Claude Code/Codex는 기존 로컬 `/mcp` URL과 인증 설정 그대로 연결하면 됩니다. MCP 초기화 시 연결마다 별도 에이전트 ID를 자동 발급하고, 클라이언트가 유지하는 `Mcp-Session-Id`로 이후 요청을 구분합니다. 같은 클라이언트 이름과 관리자 토큰을 사용해도 독립적으로 초기화한 연결은 서로 다른 신원입니다. 수동 토큰 발급이나 에이전트의 설정 파일 탐색은 필요하지 않습니다. 이전 버전에서 이미 연결 중이었다면 서버 업데이트 후 MCP를 한 번 재연결하세요.

앱이 실행하는 Claude 대화·Codex 대화·CLI 터미널의 전용 자격 방식도 유지합니다. 하나의 MCP 연결을 공유하는 서브에이전트는 같은 신원이며, 독립 제어가 필요하면 각각 연결해야 합니다. 한 에이전트가 여러 터미널을 여는 것은 가능합니다.

외부 연결은 최대 128개이며, 소유 터미널이 없는 연결은 1시간 동안 요청이 없으면 정리합니다. 터미널을 소유한 연결은 조용하다는 이유로 만료시키지 않습니다. MCP 세션을 종료(DELETE)하면 자격을 폐기하지만 SSH/서버는 종료하지 않습니다. 새 연결에서 기존 터미널을 사용하려면 사용자가 UI에서 새 Shared Terminal Key를 복사해 에이전트에게 전달합니다. 앱 재시작·작업 폴더 교체 시 MCP 연결도 다시 초기화합니다.

고급 실행기는 기존 `POST /api/mcp/agents` 전용 자격 발급 API를 계속 사용할 수 있습니다. 이 방식에서 같은 전용 토큰을 공유하면 같은 신원입니다. 토큰이나 MCP 세션 헤더를 로그·채팅·프로젝트 파일에 복사하지 마세요.

모든 에이전트는 공유 세션의 목록·출력을 읽을 수 있지만 입력·종료·삭제는 소유자만 가능합니다. 호출자가 보내는 `actor` 이름을 인증으로 사용하지 않습니다. 연결 변경은 사용자가 제공한 키로 `join_shared_terminal`을 호출합니다. 사용자는 UI에서 바로 입력하거나 Shared Terminal Key를 복사해 원하는 에이전트에게 전달할 수 있습니다.

`write_shared_terminal`, `stop_shared_terminal`, `remove_shared_terminal`에는 조회 결과의 `controlVersion`을 `control_version`으로 전달합니다. 사용자 입력과 연결 변경 때 번호가 증가하므로 A → B → A로 돌아와도 과거 A의 지연 명령은 거부됩니다. 버전 변경 후 자동 재전송하지 말고 새 상태와 사용자의 개입 내용을 확인하세요. 사용자 입력 대기는 제출/취소 후 2초의 무입력 시간을 거쳐 해제됩니다. 이것이 전경 명령 완료를 의미하지는 않습니다.

`list_terminal_agents`는 에이전트 신원·마지막 활동을, `get_terminal_resources`는 한도와 현재 사용량을 제공합니다. 2분간 요청이 없으면 **연결 확인 필요**로 표시할 뿐 끊겼다고 단정하거나 서버를 죽이지 않습니다. 외부 실행기는 필요하면 60초 간격으로 MCP ping을 보내 활동을 갱신할 수 있습니다. 앱이 관리하는 CLI 종료·대화 삭제·연결 종료에서는 해당 자격을 폐기합니다. Claude의 정상 턴 완료는 대화 신원을 유지합니다. 외부 실행기 종료 시 관리자가 `POST /api/mcp/agents/:id/revoke`로 폐기할 수 있고, 소유 세션 정리 후 `DELETE /api/mcp/agents/:id`로 목록에서 제거합니다. 등록 신원은 최대 128개입니다. 폐기되어도 그 에이전트가 띄운 서버는 유지되고 사용자가 새 키로 연결할 때까지 유지됩니다.

같은 로컬 OS 계정의 셸 실행 권한까지 격리하는 보안 샌드박스는 아닙니다. 에이전트끼리 관리자 토큰을 공유하거나 임의로 로컬 프로세스에 접근하면 OS 수준 권한은 동일합니다. 이 기능은 정상 도구 호출의 소유권·입력 충돌을 서버에서 강제합니다.

## 메모리와 부하의 범위

최대 16개 × 200,000 UTF-16 코드 단위이므로 보관 로그 본문은 약 6.1 MiB 상당으로 제한됩니다. 이 수치는 전체 앱 RSS가 아니며 문자열 임시 복사·메타데이터·입력 ID·xterm·네이티브 PTY의 메모리가 별도로 필요합니다. 입력은 세션당 초당 64 KiB, 화면 구독은 세션당 4개로 제한합니다. 브라우저가 실제로 출력을 처리한 후 ACK하며, 미처리 출력이 256 Ki 코드 단위를 넘거나 네트워크 버퍼가 2 MiB를 넘으면 느린 화면 연결만 끊습니다. SSH/서버는 계속 실행됩니다.

숨긴 화면에는 로그를 스트리밍하지 않습니다. 시스템 가용 메모리 256 MiB 미만에서는 새 세션을 거부하며 기존 작업을 임의로 종료하지 않습니다. 리소스 API는 시스템 가용 RAM과 앱 서버 RSS도 제공합니다. **터미널에서 실행한 Node/Python/빌드 프로세스 자체의 RAM·CPU, 원격 SSH 서버의 자원은 이 한도로 제한되지 않습니다.** 프로세스별 강제 자원 제한이 필요하면 컨테이너나 Windows Job Object 같은 별도 실행 격리가 필요합니다.

## 명령 제출과 응답 진단

한 줄 셸 명령은 `submit_shared_terminal_command`를 사용하면 Enter가 자동 추가됩니다. 원시 키 입력은 `write_shared_terminal`을 유지합니다. 쓰기 응답은 `inputAccepted: true`, `completion: not_tracked`이며 실행 완료를 뜻하지 않습니다. 쓰기 직후 출력은 `outputCursorBeforeWrite`부터 읽고, 이후에는 읽기 응답의 `cursor`를 이어 사용하세요. 쓰기 응답의 현재 `cursor`로 시작하면 이미 도착한 빠른 출력을 건너뛸 수 있습니다. `shell`, `lastInputAt`, `lastOutputAt`도 반환합니다. Windows 기본 셸은 cmd.exe입니다. 로그인/서버가 전경을 차지한 상태에 다른 명령을 보내지 마세요.

지연 구간은 `get_runtime_diagnostics`로 조회합니다. 자세한 범위와 재현 방법은 [agent-bridge-audit.md](agent-bridge-audit.md)를 참고하세요.

## 에이전트와 Terminal Hub 동시 보기

Terminal Hub는 작업 모드에 관계없이 메인 뷰에서 엽니다. Terminal 모드에서는 위쪽 Hub와 아래쪽 Agent CLI를 동시에 볼 수 있고, Interaction 모드에서는 에이전트 대화와 Hub를 함께 봅니다. 사이드바 Terminal Hub 또는 `Alt+5`로 열고 `새 터미널`로 셸을 만들 수 있습니다. 하단 터미널 표시와 높이는 독립적으로 조절합니다. `Alt+←/→`는 포커스가 있는 대화·터미널 영역의 탭을 순환합니다. 포커스가 밖에 있으면 현재 모드의 에이전트 탭을 선택합니다.

Interaction 모드에서는 기존 작업 패널에 표시합니다. 화면 위치를 옮겨도 메타데이터 연결과 선택 세션은 유지하며 PTY를 새로 만들지 않습니다. 숨긴 화면은 출력을 구독하지 않고, 다시 열면 같은 세션의 보관 출력을 복원합니다. 창/탭 숨기기는 프로세스 종료와 다릅니다.

참고한 외부 설계: [ryamgoh/terminal-mcp](https://github.com/ryamgoh/terminal-mcp)는 지속 세션·커서 출력·명령 완료 대기를 분리하고, [lightos/interactive-shell-mcp](https://github.com/lightos/interactive-shell-mcp)는 PTY와 화면 읽기를 결합합니다. 이번 변경은 세션 수명과 표시 위치의 분리를 적용합니다. 외부 코드를 복사하거나 다른 MCP 서비스를 추가하지 않았으며, 그 구현의 명령 완료 추적이나 headless 화면 에뮬레이션까지 도입한 것은 아닙니다.

## 셸에서 에이전트 직접 실행

앱의 일반 Terminal과 Terminal Hub에서 새 셸을 연 뒤 `claude` 또는 `codex`를 입력하면 현재 워크스페이스 MCP 설정을 자동 전달합니다. `--model`, `--resume` 등 인자도 전달됩니다. 프로젝트 전용 PATH 실행기가 실제 CLI를 찾아 실행하며 사용자 전역 설정은 변경하지 않습니다. CLI 실행 파일은 서버의 원래 PATH에서 찾습니다.

직접 실행한 에이전트는 MCP 초기화마다 독립된 Terminal Hub 소유권을 받습니다. 드롭다운에서 기존 Shell을 중지할 필요가 없습니다. 기존 셸에는 환경이 소급 적용되지 않으므로 업데이트한 서버에서 새 터미널을 여세요. 앱 밖에서 연 터미널이나 실행 파일 절대경로 호출은 이 자동 실행기를 거치지 않습니다. 워크스페이스 밖으로 이동하면 잘못된 프로젝트 연결을 방지하기 위해 실행을 거부합니다.

## 키로 에이전트 연결

원하는 터미널에서 **Shared Terminal Key 복사**를 누르고 키를 에이전트에게 전달합니다. 에이전트는 `join_shared_terminal({key})`로 기존 터미널에 연결하고 입력 제어권을 받습니다. 드롭다운 인계는 필요 없습니다. 셸이나 SSH/서버 프로세스를 재시작하지 않습니다. 사용자는 바로 타이핑하면 입력 우선권을 받습니다. 별도 조작 전환 버튼은 없습니다.

새 키를 복사하면 이전 키는 무효입니다. 한 에이전트가 사용한 키는 다른 에이전트가 사용할 수 없으며, 사용자 입력 후 같은 에이전트는 새 키 없이 최신 상태로 재개합니다. 다른 에이전트로 연결을 바꾸려면 새 키가 필요합니다. 키는 터미널 목록·출력·상태 알림에 포함하지 않습니다. 서버 재시작이나 세션 종료 후에는 사용할 수 없습니다. 연결해도 현재 실행 중인 프로그램은 유지되므로 출력 상태를 먼저 읽은 뒤 입력해야 합니다.

## 자동 입력 우선권

사용자 키 입력은 즉시 우선하며 매 입력마다 제어 버전을 갱신합니다. 이전 버전을 사용한 에이전트 입력은 거부합니다. 사용자가 작성 중인 줄은 시간만 지나도 풀리지 않습니다. Enter 또는 Ctrl+C/Ctrl+D로 입력을 제출·취소하고 2초 동안 추가 입력이 없으면, 기존 연결 에이전트가 최신 버전과 출력을 읽은 뒤 입력을 재개할 수 있습니다. 상태의 `userInputPending`이 입력 대기 여부를 알려줍니다. 이 규칙은 입력 충돌만 관리하며 실행 중인 SSH·서버·명령을 자동 중지하거나 완료를 판정하지 않습니다.

## Ctrl+Backspace와 SSH 키 입력

일반 Terminal과 Terminal Hub 모두 **Windows 키 / SSH·Linux 키** 설정을 제공합니다. 로컬 cmd에서는 Windows 키를, SSH의 일반 Linux 셸에서는 SSH·Linux 키를 선택하세요. Ctrl+Backspace는 Windows 모드에서 Ctrl+H, SSH·Linux 모드에서 Ctrl+W를 전송합니다. 설정은 브라우저에 세션별로 저장되며 기존 셸을 재시작하지 않습니다. SSH를 종료하면 Windows 키로 되돌릴 수 있습니다. 원격 프로그램이 키 바인딩을 변경했다면 해당 프로그램의 설정이 우선합니다.
