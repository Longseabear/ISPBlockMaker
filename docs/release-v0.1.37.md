# v0.1.37 · Terminal Hub

- Project Skills 위에 **Terminal Hub**를 추가했습니다. SSH, 개발 서버, 빌드 세션을 사용자와 에이전트가 함께 보고 조작할 수 있습니다.
- 일반 실행은 백그라운드에 유지하고 로그인·사용자 입력·함께 볼 오류 등 필요한 경우에만 에이전트가 화면 표시를 요청합니다. 패널을 숨겨도 프로세스는 계속 실행됩니다.
- 에이전트별 인증 정보와 세션 소유권을 도입했습니다. 다른 에이전트는 출력을 조회할 수 있지만 입력·종료·삭제는 소유자만 할 수 있습니다. 명시적인 인계와 사용자 제어권 전환을 지원하며, 인계 전의 지연 명령은 거부합니다.
- Claude/Codex 대화와 앱에서 실행한 CLI에 별도 MCP 인증 정보를 주입합니다. 한 에이전트가 여러 세션을 소유할 수 있고, UI에 작업명과 에이전트 ID를 표시합니다.
- 세션 수, 출력 버퍼, 입력 속도, 재시도 기록, 화면 구독 수를 제한합니다. 느린 화면 연결은 분리하고 메모리가 부족하면 새 세션 생성을 거부합니다.
- Terminal Hub MCP 도구 10개와 양쪽 에이전트용 기본 스킬, 오프라인 사용 설명서를 제공합니다.
- 대화의 지시 대기 상태에 어떤 대화의 작업 완료를 기다리는지 표시합니다.

## 지원 범위와 업데이트

기본 한도는 에이전트당 4개·워크스페이스당 16개 세션이며, 종료 후 보관 중인 세션도 포함합니다. 로그는 세션당 최근 200,000 UTF-16 코드 단위만 보존합니다. 터미널에서 실행한 프로그램 자체의 RAM·CPU 또는 원격 SSH 호스트의 자원은 강제 제한하지 않습니다. 같은 로컬 OS 계정의 프로세스를 보안 격리하는 기능은 아닙니다.

별도 MCP 프로세스도 같은 토큰을 쓰면 같은 에이전트로 취급됩니다. 외부 실행기는 로컬 관리자 API의 `POST /api/mcp/agents`로 전용 토큰을 발급받아 연결마다 설정하세요. 앱에서 실행한 에이전트에는 자동 적용됩니다. 연결이 끊기거나 조용해져도 실행 중인 서버를 임의로 종료하거나 소유권을 자동 이전하지 않습니다.

작업을 저장하고 기존 앱 서버를 종료한 뒤 설치하세요. 앱 서버 재시작 시 터미널 세션은 복원되지 않습니다. 서버와 에이전트를 다시 시작하면 새 도구·스킬을 사용할 수 있습니다. 사용자 수정 스킬은 보존하며 업데이트 후보로 제공합니다.
