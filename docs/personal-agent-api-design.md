# Personal Agent API — 설계안

상태: 최초 설계 기록. 현재 중앙 Hub에서 허용된 workspace/session ID로 요청을 전달하는 localhost API가 구현되었다. 설정은 Windows 서버 관리의 에이전트 프로그램 연결 탭에 있다. 정확한 경로·지원 범위·예제는 [Agent API 사용법](personal-agent-api.md)을 따른다. 아래의 짧은 경로, harness_id 지정, LAN 실행 및 기타 제안은 현행 계약으로 해석하지 않는다. 클라이언트 연결 프로그램은 포함하지 않는다.

## 목적과 경계

클라이언트 연결 프로그램이 기존 Interaction 엔진에 작업을 요청하고 결과를 받아 클라이언트로 전달한다. 새로운 에이전트 런타임을 만들지 않는다. 회사 Claude Code와 기존 Codex 연결, 워크스페이스 설정, 스킬과 MCP를 재사용한다. 웹 UI와 외부 요청은 동일한 대화 및 실행 상태를 본다. 브라우저는 닫아도 되지만 앱 서버는 실행 중이어야 한다.

읽기 전용 LAN MCP 공유와 실행 API의 자격 증명을 분리한다. 개인 API는 기본 비활성화, localhost 기본, 전용 토큰 발급/폐기, 허용 워크스페이스와 실행 권한 설정을 제공한다. LAN 사용은 별도로 켠다. 호출자가 임의 서버 경로나 실행 파일을 요청 본문으로 지정하게 하지 않는다.

## 제안 계약

공통 접두사 `/api/agent/v1`, 인증 `Authorization: Bearer <personal-token>`.

| 메서드/경로 | 역할 |
| --- | --- |
| POST /sessions | 허용 워크스페이스 ID와 엔진으로 대화 생성 |
| GET /sessions | 접근 가능한 대화와 상태 조회 |
| POST /sessions/{id}/messages | 작업 또는 추가 지시 접수, 202와 run ID 반환 |
| GET /runs/{id} | 상태, 최종 답변, 오류, 결과물 참조 조회 |
| POST /runs/{id}/cancel | 해당 실행 중단 요청 |
| POST /runs/{id}/answers | 해당 실행에서 생성된 질문/권한 요청에 응답 |
| GET /events?after={event_id} | SSE 이벤트 수신과 재연결 |
| GET /artifacts/{id} | 해당 토큰과 워크스페이스 범위의 결과물 조회 |

변경 요청에는 `Idempotency-Key`를 사용한다. 키 범위는 토큰의 주체와 워크스페이스이며 키·정규화된 본문 해시·접수 결과를 디스크에 기록한다. 같은 키/입력은 기존 결과를 반환하고 다른 입력은 409로 거절한다. 네트워크 수준의 exactly-once 실행을 약속하지 않는다. 접수와 실제 실행 사이의 종료로 실행 여부가 불확실하면 상태 조회 및 명시적 재개가 필요하다.

메시지 예시:

```json
{
  "text": "디노이징 검증 하네스로 테스트하고 결과를 요약해줘.",
  "harness_id": "denoise-validation",
  "delivery": "queue",
  "external_ref": "client-request-12345"
}
```

`external_ref`는 상관관계용 불투명 식별자다. 서버가 클라이언트 주소로 메시지를 보내거나 URL에 접근하는 명령으로 해석하지 않는다. 하네스는 이름 대신 안정적인 ID로 지정하고 실제 실행 모드를 확인한다. 대화가 이미 다른 워크스페이스/엔진에 묶여 있으면 임의 변경하지 않는다.

## 상태와 동시성

대화는 문맥, run은 요청 1개의 실행을 나타낸다. run 상태는 `queued → running → completed/failed/cancelled/interrupted`, 질문이 있으면 `waiting_input`으로 전환한다. 취소 요청 수락과 실제 취소 완료를 구분한다. 질문 응답에는 request ID를 사용하고 만료되거나 다른 실행의 요청이면 거부한다.

같은 대화는 직렬 처리하고 대화 사이에는 설정된 동시 실행 한도 안에서 병렬 실행한다. 기본 추가 지시는 큐에 보존한다. `delivery: steer`를 제공한다면 현재 엔진의 지원 여부를 검사하고 미지원은 명시적으로 거절한다. 조용히 기존 지시를 덮어쓰거나 큐 동작으로 바꾸지 않는다.

서버 재시작 시 완료 기록은 보존하고 진행 중 실행은 `interrupted`로 표시한다. 명령이나 외부 변경이 이미 발생했을 수 있으므로 자동으로 재실행하지 않는다. 재개는 현재 상태 확인과 명시적인 요청을 통해 수행한다.

## 이벤트와 결과 전달

이벤트 종류: `run.started`, `run.progress`, `run.input_required`, `run.completed`, `run.failed`, `run.interrupted`. 각 이벤트에는 고유 ID, session ID, run ID, 시각, 유형별 payload를 포함한다. 진행은 공개된 도구/단계 메타데이터이며 숨겨진 추론을 의미하지 않는다.

첫 버전은 SSE와 상태 조회를 제공한다. 연결 프로그램이 이벤트를 받아 클라이언트에 전달한다. 이벤트는 중복 수신될 수 있으므로 소비자는 event ID로 중복을 제거한다. 보존 범위를 벗어난 after ID는 명시적인 오류와 상태 재조회 안내를 반환한다. 웹훅은 후속 기능이며 첫 버전에 임의 콜백 URL 실행을 넣지 않는다.

최종 답변은 텍스트와 결과물 ID로 반환한다. 이미지/HTML의 원시 바이트를 대화 본문에 자동 삽입하지 않는다. 다운로드는 결과물별 접근 검사를 거치며 원시 로컬 경로를 입력받아 파일을 읽어주는 API를 만들지 않는다. 이미지 표시 요청이 모델 이미지 입력으로 바뀌지 않도록 기존 뷰어 표시와 분석을 구분한다.

## 구현 시 검증 게이트

- 요청 재전송/충돌/동시 접수에서 중복 실행 방지.
- 동일 대화 큐 보존, 서로 다른 대화 동시 실행, 현재 엔진의 steer 지원 차이.
- 실행 직전/중간 서버 종료와 재시작 시 불확실한 작업의 자동 재실행 방지.
- SSE 끊김/재연결/중복/보존 기간 만료와 완료 결과 재조회.
- 승인 만료, 토큰 폐기, 워크스페이스 변경, 다른 워크스페이스 결과물 접근 차단.
- 읽기 공유 MCP 자격 증명으로 실행 불가.

이 기록 이후 구현된 범위와 실행 방법은 위 사용법 문서를 참조한다. 에이전트 프로그램 전송은 서버가 수행하지 않는다.
